# Cabinet Manufacturing Capability V1

## Official Use Case

Design Base Cabinet with Two Doors and One Internal Shelf

## Business Problem

Users need a reliable way to define a base cabinet that can be engineered, validated, and prepared for manufacturing with minimal manual rework.

The use case focuses on reducing common cabinet-design mistakes such as inconsistent panel sizing, missing hardware, missing back panels, missing shelf support, and incomplete manufacturing outputs.

## Target User

- Furniture designers
- Cabinet designers
- Manufacturing engineers
- Technical sales users preparing a quotation draft

## Supported Scenario

A user creates a base cabinet with:

- configurable width
- configurable height
- configurable depth
- two doors
- one internal shelf
- associated hardware and manufacturing outputs

The scenario represents a standard base cabinet workflow where the product can be validated for engineering and manufacturing readiness and then exported into the expected downstream outputs.

## Required Objects

- Cabinet
- Side Panels
- Top Panel
- Bottom Panel
- Back Panel
- Two Doors
- One Internal Shelf
- Hinges
- Shelf Pins
- Edge Banding

## Required Outputs

- 3D Cabinet View
- Engineering Validation
- Manufacturing Validation
- BOM
- Cut List
- Hardware List
- Cost Summary
- Readiness Summary
- Quotation Draft

## Acceptance Criteria

- User can create the cabinet
- User can change width/height/depth
- Panels update consistently
- Doors remain aligned
- Shelf remains inside cabinet
- Back panel is represented
- Edge banding is represented
- Required hardware is represented
- Engineering validation can be run
- Manufacturing validation can be run
- Required outputs can be generated or are explicitly marked pending

## V1 Scope Notes

This use case contract is limited to the documented product capability for V1.

The focus is on product definition, validation, and documentable outputs for a base cabinet with two doors and one internal shelf.
